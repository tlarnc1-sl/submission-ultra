# 提出物Ultra

**提出期限を記録するアプリではない。まだ間に合う「最後の開始時刻」を知らせ、提出忘れを防ぐアプリ。**

締切そのものではなく「これを過ぎたらもう間に合わない時刻」を計算し、その瞬間に、時刻・マナーモード・おやすみモードに関係なく本気の通知を出します。

---

## 中心にある考え方

### 最後の開始時刻

緊急通知の時刻は、必ず次の式で決まります。

```
最後の開始時刻 = 期限 −（本気でやれば終わる作業時間 ＋ 余裕時間）
```

この時刻を過ぎても未完了なら、もう「あとでやる」とは言えません。Ultra は緊急通知を出します。

### 入力は最小限

- 提出物の名前
- 種類（Classroom / 紙）
- 期限（紙の場合は「終わらせる時刻」と表示）
- 本気でやれば終わる作業時間
- 管理をする先生（任意）

余裕時間は全課題共通の設定で、初期値は 30 分です。

### テスト通知は本番通知そのもの

テスト専用の通知処理は作りません。テスト通知と本番の緊急通知は、**通知チャンネル・音・振動・DND 例外・表示内容まで同じ関数・同じ経路**を通ります。違うのは渡す提出物データがテスト用であることだけです。

テストが成功したことは、本番の緊急通知がその端末設定で動くことの証明でなければなりません。

### 権限は信頼ではなく確認

権限は一度許可されたからといって、永遠に有効とは限りません。起動のたび、そして状態画面を開くたびに次を確認します。

1. 通知を表示できる
2. 正確な時刻に鳴らせる
3. おやすみモード中でも鳴らせる
4. 緊急チャンネルがサイレント例外になっている
5. バッテリー最適化から除外されている（推奨）
6. 全画面アラームを最前面に表示できる（推奨）

不足があれば曖昧に動作を続けず、「緊急通知できない」ことを明示し、該当のシステム設定へ直接案内します。

### 利用者を騙さない

Android は最終的な通知設定の主導権を利用者に残しています。Ultra は「絶対に鳴る」と根拠なく約束しません。代わりに、今この端末で緊急通知が成立するかを確認し、本番と同じ通知を実際にテストできるようにします。

## 主な機能

- **緊急通知**：最後の開始時刻に、DND・マナーモードを越えてアラーム音で通知
- **全画面アラーム**：ロック画面の上に全画面表示。締切までのカウントダウン（0.001 秒刻み）と「開く／完了にする」
- **通知アクション**：通知トレイから直接「完了にする」
- **リマインダー通知**：締切の 3 日前から毎日。緊急通知とは別チャンネルで、マナーモードを尊重する
- **ホーム**：最も切迫した 1 件をヒーロー表示。全課題がリアルタイムでカウントダウン
- **完了済み**：開始リミットより平均どれだけ早く完了できたかを集計。履歴は表形式で、削除・未完了に戻すが可能
- **テスト通知**：緊急・リマインダーをその場で発火。全画面の確認用に「10 秒後にテスト」も用意

## 技術構成

- Kotlin + Jetpack Compose（Material 3）
- Room（ローカル DB）/ DataStore（設定）
- AlarmManager `setExactAndAllowWhileIdle()` による正確な発火。**WorkManager は時刻保証がないため緊急通知には使わない**
- Hilt は使わず、軽量な `AppGraph`（ServiceLocator）で依存を組み立て
- クラウド同期なし・ネットワーク通信なし・**完全にローカル完結**

### パッケージ構成

```
app.submissionultra
├─ data/          Assignment, DAO, Room DB, Repository, 設定
├─ domain/        Timing（最後の開始時刻・緊急度の計算）
├─ notification/  EmergencyNotifier（唯一の発火経路）, AlarmScheduler, Receivers
├─ readiness/     起動時の権限・通知環境チェック
└─ ui/            home / edit / completed / settings / alarm / components / theme
```

## ビルド方法

```bash
git clone https://github.com/tlarnc1-sl/submission-ultra.git
```

1. Android Studio でプロジェクトを開く
2. SDK Platform **37** をインストール（`compileSdk = 37`）
3. Run

| 項目 | 値 |
|---|---|
| compileSdk | 37 |
| targetSdk | 36 |
| minSdk | 24 |
| JDK | 17 以上（Android Studio 同梱のもので可） |

アプリのバージョンは `gradle/libs.versions.toml` の `appVersionName` / `appVersionCode` で一元管理しています。

`gradle.properties` の `android.disallowKotlinSourceSets=false` は、KSP（Room のコード生成）と AGP 9 の組み込み Kotlin を共存させるために必要です。

## 必要な権限

| 権限 | 用途 |
|---|---|
| `POST_NOTIFICATIONS` | 通知の表示（Android 13+） |
| `SCHEDULE_EXACT_ALARM` | 最後の開始時刻ちょうどに発火させる |
| `ACCESS_NOTIFICATION_POLICY` | おやすみモードの例外として鳴らす |
| `USE_FULL_SCREEN_INTENT` | ロック画面上に全画面アラームを出す |
| `SYSTEM_ALERT_WINDOW` | 通知が溜まっている／ロック解除中でも全画面を最前面に出す |
| `RECEIVE_BOOT_COMPLETED` | 再起動後にアラームを再設定する |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 省電力による遅延を避ける（推奨） |

いずれも端末内で完結し、外部への送信は一切ありません。

## デザイン方針

UI はミニマルであること。装飾のための要素、意味のない色分け、過剰なアニメーションは入れません。**絵文字はアイコン・ラベル・通知文言を含め、アプリ内のあらゆる場所で使用しません。** 提出物の一覧では緊急度による色分けを行わず、文字の大きさと太さだけで優先度を表します。
